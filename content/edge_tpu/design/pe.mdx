## Overview

This project's processing element is basically a 3-stage pipelined MLA weight-stationary unit with validity flags as well. 

Basically it accepts a constant 1-cycle flow of values from the Activation or Partial Sum inputs (A_i and P_i respectively),
and validity inputs (Av_i, Pv_i respectively) as well. After 3 cycles it outputs a the result of the MLA, and asserts the output valid flag.

Because of the weight-stationary nature of this element, the activation path can be used to store a weight, so we also add a small interface for latching/clearing this stored weight directly on the PE

A complete waveform showing weight storage and a computation pass is given below with a docs only `STATE` variable that shows whats happening, 
Basically this PE implements MLA as `P_o = (A_i * B_r) + P_i` where P_o shows up after a 3 cycle delay

## Implications

This implementation, specifically the 3-stage pipelining allows for a greater core frequency, but it also complicates the surrounding logic. We see that the data for `A_i` and `P_i` (as well as the corresponding validity flags) must arrive in lockstep.
And since this PE feeds the next (downward, or right) connected neighbour after 3 cycles, the row inputs to those neighbours need to be skewed by 3 cycles, not 1 cycle as desribed on the architecture page. For how we deal with the skewing, you can take a look at the next page
All i will say for now is: FIFOs
